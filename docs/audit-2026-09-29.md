# Ser8 audit iteration — 2026-09-29

Scope: bookmark import and ownership, buddy like-sharing controls, release checks,
and the live Ser8 backup failure. This is a focused iteration, not a complete
security or performance audit.

## Findings addressed

- X bookmark imports flattened folder hierarchy. The importer now previews the
  destination account and unique entries, preserves documented folder mappings
  and empty nested folders, rejects conflicting mappings before writes, and
  reuses paths transactionally. See [the import guide](x-bookmark-import.md).
- Saved pending imports disappeared from the owner's bookmark list. Owners now
  see their own pending copies with a moderation label; other users' pending
  posts and rejected posts remain excluded. Folder counts follow that visibility.
- Failed like-sharing saves left edited controls on screen. Controls now restore
  the last saved privacy settings and audience selections, and serialize writes.
- The nested folder breadcrumb labeled “All bookmarks” opened the root folder.
  It now returns to the full collection.
- Ser8's daily GitHub backup failed after normal cleanup reduced `ip_activity`
  and `post_view_visits`. The guard now allows decreases only in explicitly
  documented tables with deletion/expiry paths. Durable or unknown tables remain
  guarded; any missing table or malformed count manifest blocks publication.
  Compressed dump byte size is informational, not evidence of content loss.
- Database bookmark tests were ignored by ordinary CI. CI and release now run
  them explicitly against disposable PostgreSQL databases; CI also exercises the
  backup count guard.

## Validation before merge

Rust format, clippy with warnings denied, workspace tests and build passed.
Both database bookmark tests passed against isolated local databases. Web type
checks, tests and production build passed. Eight parser and three backup guard
cases passed, including the production expiry failure and durable-loss rejection.

Authenticated browser checks used a disposable local `u/techmore` fixture,
not the production account: nested import saved two posts under Research/Linux,
preserved Research/Empty, and repeating it left three folders and two bookmarks.
Injected network failures restored General-only sharing, selected visibility and
an unchecked follower. Production verification is recorded in the release and
deployment workflow receipts.

## Remaining inputs and opportunities

The user's actual X bookmarks have **not** been transferred: no personal archive
or folder mapping was available. The importer accepts the standard flat archive;
folder hierarchy requires explicit mapping data and cannot be inferred from IDs.
Cross-posted content may be public even though the saved bookmark is private.

The tracked source `VERSION` on Ser8 is older than the deployed release badge;
use the deployment receipt and live web badge for release identification. A later
iteration can make the source/runtime version diagnostics consistent.
