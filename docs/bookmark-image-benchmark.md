# Private bookmark image comparison

The host-native benchmark compares the float ONNX export of `qualcomm/MobileNet-v3-Small` with `qwen3.5:2b` on the same saved bookmark images. MobileNet emits ImageNet object labels; Qwen emits General/R/X suggestions under the local rating policy. Those are different tasks, and neither output is ground truth. A Qwen rating whose explanation contradicts the policy is flagged. Human-reviewed labels are required for a meaningful accuracy comparison.

Results stay on the host in `~/.local/share/swartzit-mobilenet-trial/results.sqlite`. The `runs`, `items`, and `predictions` tables preserve separate runs, source post/media identifiers, image hashes, model digests, configuration, raw output, errors and timings. Prepared 512-pixel JPEGs are retained privately by SHA-256 in `images/` so inputs can be matched across runs. SQLite files and cached images have restrictive permissions. Timings cover ONNX inference only versus the full Qwen local API call, excluding image downloads; they are not equivalent workloads.

A baseline run snapshots the account's approved bookmark image URLs at creation. It labels the full set with MobileNet first, then runs Qwen over the same cached images. It does not process video frames or posts without image attachments, and inaccessible or unsupported images are recorded as errors. To create another full run, execute `venv/bin/python benchmark.py --handle HANDLE --name RUN_NAME --create-only` in the state directory, then invoke `install-bookmark-image-benchmark.sh HANDLE RUN_ID` to start the resumable user service. Distinct runs append results instead of replacing prior measurements. More tools can add rows to `predictions` using a distinct tool name and model digest. Resume checks that model digests remain the same.

Run `python3 bookmark-benchmark-summary.py` to see per-run counts, median timings, Qwen ratings, and internal policy conflicts. The summary contains no bookmark text or images. Inspect the local `results.sqlite` for individual results. The benchmark does not write Swartzit bookmarks or post ratings.

To retry failed items from a finished run without changing its results, use the same model files and runtime with `venv/bin/python benchmark.py --handle HANDLE --retry-failed-from RUN_ID --name RETRY_NAME`. This creates a separate run, copies existing predictions and cached-input references, and retries only items marked as errors. Account, model digests and relevant configuration must match; cached image hashes are rechecked during execution. The original run and its errors remain intact. The command requires a running Ollama service.

## Candidate model

`litert-community/gemma-4-12B-it-litert-lm` is cataloged for a later image trial. The model card identifies text, image and audio inputs, a roughly 6.9 GB model file, and LiteRT-LM 0.17 or later. It has not yet been downloaded or scored on Ser8. Actual memory use, compatibility and speed on this AMD host need measurement; model-card figures from other hardware are not Ser8 results. Record a separate run and model digest when evaluating it, and compare against held-out human labels when enough are available.
