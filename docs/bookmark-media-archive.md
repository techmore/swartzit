# Local bookmark media archive

The guest-side `archive-bookmark-media.py --handle HANDLE` snapshots the X image, video, poster, and profile-image URLs associated with an account's saved posts. It copies original bytes into `state/bookmark-media-archive/objects/`, names objects by SHA-256, and writes an atomic URL index only after a download is complete. It allows only HTTPS X image/video hosts, streams files up to 4 GiB, retries failures up to three times, and stops before disk free space reaches the configured floor. The included systemd timer runs again periodically to discover newly saved items.

`SourcePost` uses `/archived-media?src=...` for X media. The web route serves locally saved content with video byte-range support; until an item has been archived it redirects to the original X URL. Original source URLs remain in the database. The route validates the host, metadata, object name, MIME type and size. This archive is separate from the standard media upload directory; it is persistent local storage, not a second backup copy.

The private `manifest.jsonl`, refreshed after a completed archive pass, links bookmarked post text and source metadata to original media file hashes, paths and download status. Human rating corrections include their content hash so later training pipelines can verify that a label applies to the correct reviewed version. Generate a current partial manifest with `python3 /var/lib/swartzit/state/export-bookmark-media-manifest.py --handle HANDLE`. Existing benchmark runs retain their own exact 512-pixel JPEG inputs. For future benchmark runs, set `SWARTZIT_ARCHIVE_SITE` to the HTTPS Swartzit origin to read the local archive first, with the endpoint falling back to X for items not yet saved.

The archive includes only media URLs present in captured posts; unavailable or protected source posts and unsupported content cannot be reconstructed. Full video files are retained, but extracting video frames or training a model is a separate task. Review `state/bookmark-media-archive/archive.sqlite` for pending or failed downloads. The manifest and originals reside in the guest state directory with access limited to the service account.
